# 默认参数与接口支持范围

[返回主文档 AGENTS.md](../AGENTS.md) · [建线流程](create-line.md) · [OSM 数据](osm-data.md)

## 1. 线路建设规格

| 线路类别 | 默认轨道 | 默认层级 | 当前工具支持 |
| --- | --- | --- | --- |
| 地铁 | Medium speed | 实际地面 `0`、高架 `1`、地下负层级 | 建站、延伸及道岔已支持；桥隧分界须保留控制点 |
| 城间高铁 | High speed | 高架，`depth=1` | 层级可用；High speed 类型参数尚未开放 |
| 普速铁路 | Medium speed | Ground，`depth=0` | 建站、延伸及道岔显式传入 `0` |
| 有轨电车 | Tram | 实际地面／桥隧 | 先完成 Medium 蓝图创建与连接，再用 `set_tram_track` 转换；采购仍用替代车辆 |

这些是项目建设规则，适用于新线路轨道、站台和道岔。地铁按实际区间还原，使用 OSM 的 `bridge`、`tunnel`、`layer` 记录桥隧依据；建筑通道 `tunnel=building_passage` 不等于地下隧道。用户确认的现场事实优先并写入规划，清河站明确采用高架 `depth=1`。已有线路须先读取现场、保留玩家改动，再经原生重建流程修改。

**避免造成信号阻塞的跨线平交。** 普通道岔、交叉渡线保持同层属于正常配线，无须统一立交或下沉到 `-3`。不同线路的正线交叉若导致机外等待，应调整其中一线的站台和邻近过渡轨道层级，保留换乘。`set_track_depth` 支持 `-3..3` 并同步附属建筑；单独修复棕色区域层级使用 `sync_platform_building_depth`。

当前适配版本中，Medium 原生类型为 `3`，游戏轨道上限 160 km/h；High speed 类型为 `1`，游戏轨道上限 350 km/h。枚举依赖游戏版本，速度不是承诺运营速度。以 `game_version.py` 的 EXE 哈希校验为准；车型、曲线及运行计划还会限制实际速度。

`server.py` 与 `bridge.js` 当前将新轨道／站台类型固定为 `3`，既有端点连接也要求 Medium。类型编辑支持 `set_medium_track` 和 `set_tram_track`，没有通用 `set_track_type`。Tram 原生类型为 `2`，内置各层限速 60 km/h，地面 `collides_ways=false`；完成全部 Medium 蓝图连接后，再对整条新线蓝图转换并重新检查曲线与原生建造冲突。类型编辑可能触发原生道岔位置微调，需读回检查。它不改变桥隧层级，也不提供有轨电车采购接口。高铁建设前需要贯通创建、连接、延伸、站台、道岔及类型编辑的参数与验证，并适配合适车辆；仅修改文档或把 `depth` 设为 `1` 不会得到高铁。

## 2. 车站、几何与命名

| 项目 | 默认／约定 | 实现边界 |
| --- | --- | --- |
| 车站标签 | `Name and pax` | `create_platform` 自动设置并读回；原生标签值 `1` |
| 站名 | 规划确认的中文名 | `rename_station`；保留其他参数，带标签集合的站点暂会拒绝编辑 |
| 站台 | 双站台，地铁规划长度 140 实际米 | API 接受端点，不自动生成 140 米几何；需做 Mercator 尺度换算 |
| 配对轨道间距 | 原生命令字段 `5` | 当前桥接常量，不是可调 MCP 参数 |
| 区间 | 默认双线 | 端点连接及新段 `dual=True`；道岔工具创建单线连接 |
| 线路代码 | 显式传城市和线路前缀 | 如 `bj-3`、`nyc-a`；不要依赖函数历史默认值 `bj-1` |
| 环线方向 | 内外环分别建立运营线路 | 如 `bj-2i`、`bj-2o`，对应独立车辆编号空间 |
| 列车编号 | `<线路代码>-0001` 起递增 | 查全车队后取该前缀最大序号加一；不能重复 |
| 内部 ID | 原生 uint64 的十进制字符串 | 不转成 JavaScript Number，不改写内部 ID |
| 颜色 | 规划显式指定 `#RRGGBB` | 省略则保留；二号线 `#00529B` 只是线路示例 |

站台规划长度应大于实际编组长度。140 米适用于现有 120 米六节替代编组，不是高铁或所有普速列车的默认长度。

## 3. 车辆、票价和班次

当前 `purchase_six_car_trains` 仅购买内置 Kayou 231：6 节、120 米、900 人、最高 120 km/h，原生命令采购价为每列 13,200,000 游戏货币。它是地铁运营替代车型，不是北京真实车型，也不是通用高铁采购接口。

购车调用默认 `count=1`，允许 `1..40`。二号线每方向 6 列是已采用的配车方案，不是所有新线路的默认数量。根据一圈／往返时间 `T` 和目标间隔 `h` 估算 `ceil(T/h)`，再按实际拥堵、折返和运力调整；不要在改名失败时重新购车。

客运服务值为 `2`；`0` 关闭，`1` 技术服务。购车工具会分配线路自动运行，之后显式设置参考列车和客运服务。现有接口没有可直接设置任意发车间隔的通用工具；增配车辆可改变自动运行间隔，最终仍需观察验证。

票价没有统一的新线经济默认值。`set_line_name` 的 `base_fare=None`、`fare_per_km=None` 表示保留原值，空线路也不应假定已有合适票价。当前北京任务按玩家调整采用 `25 + 5/km`；旧试验的 `25 + 10/km` 不作为新线默认，不覆盖玩家现有设置。这不是现实票制或普遍最优方案。用户不要求继续测收益时，不自动开启票价试验。

## 4. 参数限制与运行

| 参数／工具 | 当前限制 |
| --- | --- |
| 世界端点坐标 | 建站／新建段各坐标绝对值不超过 21,000,000，且有限 |
| 站台端点距离 | 50..500 世界米 |
| 新段／延伸距离 | 1..10,000 世界米 |
| `depth` | 原有建站／延伸／道岔工具支持 `-1/0/1`；`set_track_depth` 和单线连接工具支持整数 `-3..3` |
| `create_track_segment` | 没有 `depth` 参数，固定地下 Medium；不能直接用于高架或地面新段 |
| 道岔位置比例 | `0.01..0.99`，沿节点的 previous 边定位 |
| `set_track_depth` | 每次 1..500 节点 |
| ReBP／Medium 类型编辑 | 每次最多 5,000 节点；类型编辑要求蓝图 |
| 轨道网络查询 | 遍历含分支，最多 5,000 节点；大网需分区方案 |
| 里程票价 | 0..10 |
| 起步票价 | 接口保护范围 0..10,000；未证明游戏真实上限 |
| 速度 | 0 暂停；最大原生值 10,000；运行验证需有停止条件 |

施工前通过 MCP 暂停。建成后先核查路径，再做有界运行验证。若进行经营比较，固定车队、站序和时段，预热后测完整 24 游戏小时，以现金净增评价。最高速度不保证精确落在目标时间，临近终点应降低速度并读回。
