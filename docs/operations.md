# 候车与 schedules 接口

适配版本：NIMBY Rails 1.19.10.5bfaea3，沿用 `game_version.py` 的 SHA256 校验。所有读取在核心边界进行；所有运营修改通过原生命令队列，禁止写入游戏存活对象。

## 读取

贷款使用 `get_company_loans()` 读取零起始索引、本金、利率、期数及提前偿还总额。`repay_company_loan(loan_index)` 要求暂停、存在未清贷款且现金足够；通过原生 CompanyLoans 命令结清，核对本金归零、现金扣款和其他贷款不变。按当前原生规则，尚未到期贷款的提前偿还额为剩余本金加剩余本金乘利率。每笔偿还前重新读取；超时不能盲目重试。此接口不提供新增贷款或修改现金能力。

| MCP 工具 | 返回内容 |
| --- | --- |
| `get_station_waiting(station_ids=None)` | 游戏时间、全站候车人数、大厅人数、乘客分组校验、有效时长样本数、样本平均／最大等待秒数、样本中超过 300 秒的人数 |
| `get_train_operations(train_ids=None)` | 列车原生 ID、编号、容量、实际载客人数、订单模式 |
| `list_schedules()` | 自动与独立班表、订单列表、班次、实例及车班关系 |
| `get_schedule(schedule_id)` | 单个班表；不存在返回 null |

候车数据是 **station 汇总**，不是独立站台计数。`waiting` 与 `hall_waiting` 分开返回。树节点和乘客分组数量均设上限，逐组人数总和必须等于原生候车总数，否则报错。人数不是乘客记录条数：每条记录可以代表多人。

时长使用原生乘客超时检查的当前段计时公式，按组人数加权；起始时间戳为零的乘客没有可用时长，排除于时长统计，但仍计入候车人数。必须同时看 `wait_sample_count`；没有有效样本时平均值和最大值为 null，不能理解为没有等待。`waiting_over_300_seconds` 也仅统计有效样本。

`orders_mode=0` 表示 autorun，`1` 表示手动 schedules。`train_ids` 是班表列车池；`train_shift_pairs` 是允许执行该班次的关系，不能当成当前正在执行该班次。接口尚未导出原生运行图、当前班次执行状态或单站台队列。

## 修改

全部班表／列车修改要求游戏暂停；先读取玩家现场，再记录待执行参数。超时或 `verified=false` 必须读回核实，不能直接重试。

| MCP 工具 | 作用 |
| --- | --- |
| `create_schedule()` | 创建独立班表，返回原生 ID、默认订单列表、班次和实例 |
| `rename_schedule(schedule_id, name)` | 修改名称 |
| `delete_unassigned_schedule(schedule_id)` | 仅删除没有列车的独立班表 |
| `create_schedule_shift(schedule_id)` | 创建班次，读回新班次和实例 ID |
| `append_schedule_order(...)` | 追加启用的、按发车时刻运行线路的顶层订单 |
| `edit_schedule_order(...)` | 按稳定 ID 修改顶层订单，保留启用状态、子订单和站点选择 |
| `delete_schedule_order(schedule_id, order_list_id, order_id)` | 删除指定顶层订单及其子订单 |
| `set_schedule_shift_instance(...)` | 修改既有实例使用的订单列表与秒数偏移 |
| `set_train_schedule_shift(train_id, schedule_id, shift_id, assigned=True)` | 切换手动模式，并允许／取消指定车班关系 |
| `set_train_autorun(train_id, line_id)` | 先原生切换模式并验证，再原生指定自动线路并验证 |

自动线路生成的班表不允许直接编辑。取消车班关系后列车仍为手动模式，不等于恢复 autorun；恢复时使用 `set_train_autorun`。原生模式切换会重新安排列车运行，不能承诺保留原有瞬时位置和班次 ID。

订单参数：

- `start_time`：班表当地午夜后的秒数，范围 0..86399；新班表默认采用首条线路时区。
- `days_mask`：周一=1、周二=2，依次到周日=64；工作日=31、周末=96、每天=127。
- `repeat_count`：1..1000 次；0 为原生 Max。
- `continue_into_next`：是否继续到下一订单。
- 新订单使用首／末线路停站，`timing_event=1` 为 Depart exactly at；0 是 Arrive exactly at。
- `offset_seconds`：-86400..86400；同一订单列表可由多个班次以不同偏移执行。

可以用早晚高峰订单、有限重复次数和多个错开发车的班次表达分时运力。具体车数、订单间隔与收车行为必须查看生成的原生时刻表并运行验证；字段读回成功并不代表已经满足 `<100` 候车目标。不提供虚构的“按小时车数”字段，也不自动增建车辆段。

修改接口检查目标对象、线路和子对象是否存在，并校验目标字段、保留设置及无关班表。读取与原生命令不会采购新车或更改票价。

## 开发及验证

`runtime_connection.py` 在同一脚本中加载 `bridge.js` 与 `operations.js`。仅 JS 适配代码修改可用 `reload_runtime_bridge()` 排空请求后重载；Python MCP 工具定义变化需要重启服务并重新发现工具。不要同时启动第二个持锁适配器。

2026-09-11 在上述锁定版本完成标准 MCP 协议实测：

- 创建／改名独立班表，添加和修改星期、时刻、次数、衔接参数；原生界面生成 17:00 与 17:02 两个班次，修改后显示 16:30 与 16:32。
- 创建第二班次，正负 120 秒实例偏移读回一致；删除指定订单，保留其它订单及班表设置。
- 暂停下将一列空载列车从 autorun 绑定到测试班次，取消关系，再通过两阶段命令恢复原线路。
- 自动班表修改、仍有列车的班表删除、不存在的实例修改均被拒绝。
- 425 个 station 的逐组人数与原生总数全部一致；读取 351 列车，测试完成后全部为 autorun，恢复 30 个自动班表，无测试班表残留。
- 运行验证推进了约 3 个游戏秒；未购车、未建造、未改票价。测试结束恢复原速度 10。
- `uv run python -m unittest discover -s tests -v`：45 项通过。

以上是接口验证，不是全日运力优化验收。尚未测量完整高峰窗口或达成候车目标。

## 线路停靠时间

`set_line_default_stop_time(line_id, seconds=10)` 使用原生 LineSetService，
要求暂停，范围为整数 1..86400 秒。保留其它线路设置以及各站的独立覆盖。
`get_line` 返回 `default_stop_seconds`，各停站返回 `stop_time_mode` 和
`stop_time_seconds`；设置默认值后必须逐站核对，不能假定覆盖了独立设置。

在锁定版本中通过真实 MCP 将 29 条地铁运营线路（含机场线、S1、西郊线；
不含亦庄 T1 有轨电车）设置为 10 秒，各停站读回均为 10 秒。
十号线原生界面同步显示 Stop time 0:00:10，外环周期从 1:33:20 缩短为
1:18:45。运行图还可能包含额外停留、信号等待及上下客耗时，10 秒设置
不代表实际每次开门至发车都恰好 10 秒。

跨线改派不会自动把列车移到目标线路。车辆可能仍在原线，无法到达新线并造成阻塞。
`set_train_autorun` 仅允许恢复到现有班表所包含的线路；跨线调车必须另行验证物理进路，不能以订单读回成功代替到达验证。

## 站台间距与独立蓝图清理

`create_platform` 的 `track_spacing_metres` 默认 5，接受 3..30 实际米正值。副轨在起点至终点方向的右侧；原生读回检查四个站台节点分别位于基准轨和指定偏距，允许 0.05 米误差。端点与站台长度仍使用世界坐标，不能把实际间距再次按 Mercator 放大。正间距 11.3393 米已在 Carroll Street 实测，读回为 11.3394 米。站外自动端点可能仍收束至 5 米，完整四线布局需要额外处理，不应直接延伸后宣称保持四线。

负值不能用于改变配对侧：锁定版本把负间距压到零；该试验选项已移除，接口拒绝负值。基准股道选择、运营方向和原生单向信号必须分别核对。

`set_blueprint_parallel_offset(node_ids, offset_metres, protected_node_ids)` 使用原生 `TrackBulkParOffset`，限定暂停状态、3..30 米正偏距、非站台蓝图副轨控制点，且副轨不得拥有结构子节点。显式保护列表必须包含其主轨，调用方还应纳入相邻站台。命令只设置绝对偏距，不设置增量或倍率；完成后核对偏距、前后连接、层级、类型、蓝图状态、信号及全部保护对象的节点字段。`get_track_network` 同时读回 `structure_parent` 和 `parallel_offset_metres`，不应把所有结构依附关系都推断为普通双线。

Carroll 两端副轨实测从原生默认 5 米改为 11.3393 米，六个保护节点（主轨与四个站台端点）保持不变；四线曲线另行绘图核对。直接移动副轨端点会被原生配对约束重置，发生验证失败时应读回，而不是反复提交位置编辑。

`discard_isolated_blueprint_platform(node_ids, protected_node_ids, remaining_building_ids=None)` 要求暂停，选择完整独立蓝图网络，轨道和附属建筑均未建成且仅涉及一个 station。通过原生 `tn::Delete` 的节点集合 `+0x20`、建筑集合 `+0xb0` 清理，验证所选对象消失及保护节点完整字段不变；`+0x50` 不是建筑集合。中断后仅在所选节点全已消失时，允许用已保存的建筑 ID 继续清理对应未建建筑。此工具不删除 station；空站另行读回并使用 `delete_empty_stations`。

本次清理经历节点已删、建筑仍在的读回失败；核实对象后只清理残留建筑，没有重放建站或已完成的节点删除。负间距失败蓝图的 16 个节点和 12 个建筑已移除，252 个保护节点读回一致。

## 终点单向信号与寻路

`get_track_node`／`get_track_network` 的 `building_tapes` 包含轨道附属信号的 ID、父节点、类型、位置与原生样式字节。锁定版本中类型 `0` 已与界面 One way 核对；不要推测其他类型或样式字节的含义。

`remove_one_way_signals(signal_ids, parent_node_ids)` 要求暂停、显式信号和父轨道 ID，最多各 100 个。原生执行前验证对象存在、类型为单向信号且父轨道已建；使用 `tn::Delete` 信号集合，执行后核对信号消失、父轨道及其余附属对象完全保留。不能用此接口删除路径信号。

删除信号后仍须核对线路路径。L 线北端实测需要重新应用未改变的首站有向节点，使线路重新计算；随后另行检查实际尾轨换向与出发站台。仅信号删除成功不能证明寻路已刷新或运营验收通过。
